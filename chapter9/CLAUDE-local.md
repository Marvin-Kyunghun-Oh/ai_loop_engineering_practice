## 개요
#### 에이전트의 역할이 분리된 환경(3-Agent)에서 `루프 엔지니어링`을 진행.
> 3개의 에이전트가 협업, 사람의 개입을 최소화하여 목표를 달성한다.
- 플래너 (무엇을 만들지 정의, 다음 작업을 선택)
- 생성자 (선택된 작업을 구현)
- 평가자 (결과물이 기준을 만족하는지 평가)

#### 에이전트 협업 문서 설계
1. `PRD.md` : '무엇을 만들지..' 플래너가 사람과 대화하며 완성.
2. `PLAN.md` : '어떤 순서로 만들지..' 플래너가 작성
3. `TASKS.md` : 다음 세션이 처리할 작업, 플래너가 작성
4. `IMPL.md` : '무엇을 구현하였는지' 생성자가 작성
5. `REVIEW.md` : 결과물이 기준을 만족하는지, 평가자가 작성
- `JOURNAL.md` : 모든 에이전트가 작업 기록을 시간 순으로 쌓음.
- `decisions/` : (플래너, 평가자) 미해결 의사결정 합의 기록 - 필요할 때만 작성 

#### 하네스 도구와 프로젝트를 분리함.
- 같은 하네스로 여러 프로젝트를 구현할 수 있음.
- 코드가 섞이지 않아 관리에 용이함.

## 알아두어야 할 사항
- 모든 문서작성 및 대화는 한국어를 기본으로 한다.
- 내가 `(프롬프트)`라는 키워드를 요청하면, 해당 또는 방금 전 프롬프트와, 에이전트의 답변 및 실행 결과를 `/prompt/seq_{어떤요청인지 요약한 제목}.md`에 보관한다.
  - 제목은 에이전트가 요약하되, 문장이 아닌 `단어 + '_'`의 조합으로 생성한다.(영어로)
  - seq는 1부터 채번된 문서번호 (없으면 1부터 시작)
  - 실제 운용: 위치는 `rss-wiki/prompt/`, 파일명은 `seq_` 접두어 없이 `{번호}_{제목}.md`(예: `1_print_random_quote.md`). 본문은 `## 프롬프트`와 `## 답변` 두 절로 나누고, 슬래시 커맨드면 확장된 프롬프트도 함께 적는다.
  - 실행 결과가 매우 긴 맥락이나 여라 절차로 이루어져 있다면 '어떤 일이 있었는 지' 순차적으로 요약만 한다.
  - 서브 에이전트로 병렬 작업하는 경우에는 모든 작업이 끝난 후 마지막에 정리한다. (결과가 완전히 나오면)
