# 0007. 비용 상한: CLI 보고 비용 누적 $38 + 1회 $5

- 상태: 확정
- 날짜: 2026-11-24

## 맥락
- v1은 비용을 기록하지 않았고 금액 상한도 없었다. `MAX_ITERATIONS`는 한 번 실행할 때의 사이클 횟수 제한일 뿐이다. 그래서 Pro 5시간 한도와 크레딧에 막혀서야 멈췄다.
- 처음 제안은 두 가지였다. 에이전트별 턴 상한(`--max-turns`), 그리고 토큰×단가표로 하네스가 비용을 직접 계산하는 방식이다.
- 사용자는 `/statusline`의 cost를 기준으로 $40 상한을 거는 방식을 제안했다. 검토 결과는 다음과 같다.
  - statusline은 대화형 세션 화면 기능이다. 하네스의 `claude -p` 하위 세션은 볼 수 없다.
  - 하지만 같은 출처의 비용 값이 `--output-format json` 결과에 있다. 하네스가 그 값을 누적하면 의도한 대로 구현된다.
  - 이 방식은 단가표 방식보다 단순하고 정확하다. 단가를 직접 관리할 필요가 없다.
  - 관리하려는 대상이 돈이므로 턴 수보다 금액 상한이 직접적이다.
- 누적 비용은 에이전트 프로세스가 끝나야 알 수 있다. 그래서 누적 상한만으로는 에이전트 1회분만큼 넘칠 수 있다. `--max-budget-usd`도 턴과 턴 사이에서만 끊으므로 마지막 턴 1회분만큼 넘칠 수 있다. (처음에는 추정이었고, 아래 "확인 결과"에서 확인했다.)

## 결정
```yaml
# harness.yml
limits:
  max_total_usd: 38     # 목표 $40 - 여유분 $2 (누적 상한)
  max_agent_usd: 5      # 에이전트 1회 상한 → --max-budget-usd
  max_turns: null       # 선택. 헛도는 경우 대비 보조 장치
```

에이전트 실행마다 다음 순서를 따른다.
1. **실행 전 검사**: `누적 + max_agent_usd > max_total_usd`이면 실행하지 않고 `HALT`("예산 소진")를 남긴다.
2. **실행**: `claude -p ... --output-format json --max-budget-usd 5`로 실행한다.
3. **기록**: 비용과 토큰 4종을 `docs/USAGE.csv`에 적고 누적에 더한다.
4. **판정**: 오류이거나 예산 상한으로 끊겼으면 그 사이클을 중단한다.

- 결과적으로 $40을 넘지 않는다. 실제로는 대략 $33~38에서 멈춘다.
- **재개**: `HALT`를 지우고 상한을 올린다. 누적 비용은 `USAGE.csv`에서 다시 읽는다.
- **필드 누락 처리**: 결과 JSON에 필수 필드(비용, 오류, 종료 사유)가 없으면 0으로 처리하지 않고 예외로 `HALT`한다. 필드명이 틀려 상한이 영원히 발동하지 않는 사고를 막기 위해서다.
- **토큰 기록**: 분석용으로만 쓰고, 반드시 종류별로 본다. 캐시 읽기 토큰은 양이 많지만 싸다.

## 검토한 대안
- **`--max-turns` 중심**: 턴 수를 금액으로 매번 환산해야 하고, 목적(돈)과 기준이 어긋난다. 선택 옵션으로만 남겼다.
- **토큰×단가표로 하네스가 계산**: 단가를 직접 관리해야 하고 요금이 바뀌면 틀린다.
- **누적 상한만 사용**: 에이전트 1회분(수 달러)만큼 넘칠 수 있다.

## 한계와 보정
- 표시 금액은 API 요금으로 환산한 값이라 Pro 크레딧 차감액과 다를 수 있다.
  - Pro 한도 안의 사용량(크레딧이 빠지지 않음)도 세므로, 보통은 실제보다 **많게** 센다. 일찍 멈추는 쪽이라 안전하다.
  - 한도 초과 후 같은 단가로 차감되는지는 확인하지 못했다.
- 사용자는 "대략 비슷하면 충분하다"고 판단했다.
- **보정 절차**: 첫 실행은 `max_total_usd: 10`으로 돌린다. 크레딧 감소량과 `USAGE.csv` 합계를 비교한다. 비슷하면 $38로 올리고, 차이가 크면 비율만큼 조정한다.
  - 0011 이후: 보정은 스모크 테스트로 한다.
  - 주의: Pro 한도 안에서 돌리면 크레딧이 빠지지 않아 비교가 되지 않는다. 그래서 보정은 한도를 다 쓴 상태에서 한다.
  - 스모크 1회(약 $1)로는 차이가 작아 비교가 어려울 수 있다. 그때는 여러 번의 합계로 비교한다.

## 확인 결과 (2026-11-24)
haiku로 짧은 실행 3번을 돌려 확인했다. 비용은 합계 약 $0.007이었다. 샘플은 `src/test/resources/claude-result/`에 있다.
- **비용 필드**: `total_cost_usd`. 모델별 값은 `modelUsage.{모델}.costUSD`이고 `costBasis`는 `"list"`(정가 기준 환산)다.
- **예산 상한 도달**: 상한을 $0.001로 두자 2턴째에 멈췄다. 이때 결과는 `subtype: error_max_budget_usd`, `is_error: true`, 종료 코드 `1`, `result: null`이었다. 실제 비용은 $0.00196으로 상한을 **턴 1회분 넘긴 뒤** 멈췄다. 여유분 $2가 필요한 이유가 확인됐다.
- **턴 상한 도달**: `subtype: error_max_turns`, 종료 코드 `1`.
- **판정 기준**: 종료 코드는 상한 도달과 오류가 모두 `1`이라 쓸 수 없다. `subtype`으로 판정한다.
- **미확인**: 사용량 한도 도달 시 출력 형태. 일부러 재현할 수 없어서, 처음 발생할 때 원본 로그로 확인한다.
