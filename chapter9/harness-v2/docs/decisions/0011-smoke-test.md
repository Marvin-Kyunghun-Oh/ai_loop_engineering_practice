# 0011. 샘플 프로젝트로 실제 `claude` 스모크 테스트

- 상태: 확정
- 날짜: 2026-11-24

## 맥락
- `DESIGN.md` 초안의 처리 방식은 이랬다. 실제 `claude`를 부르는 테스트는 비용 때문에 만들지 않고, 실제 연동은 첫 실행으로 확인한다.
- 이 축소는 Claude가 사용자에게 묻지 않고 스스로 정한 것이었다. 사용자가 이를 지적했다.
- 이 방식에는 구멍이 있었다.
  - 첫 실행은 아직 정하지 않은 대상 프로젝트(0004)에 달려 있다.
  - 그래서 프롬프트 형식이나 권한 패턴의 문제가 진짜 프로젝트를 정식 비용으로 돌릴 때 처음 드러난다.
  - 비용을 아끼려던 결정이 오히려 더 비싼 곳에서 문제를 발견하게 만든다.
- 사용자는 샘플 PRD를 만들어 실제로 돌려 보자고 제안했다.

## 결정
- 단위 테스트(`./gradlew test`)는 지금처럼 가짜 실행기를 쓴다. 무료이고 매번 돈다.
- 이와 별도로 **스모크 테스트**(`./gradlew smokeTest`)를 둔다. 실제 `claude`를 쓰고 수동으로 실행한다. `check`에는 연결하지 않는다.
  - 샘플 프로젝트에는 할 일이 1~2개인 아주 작은 PRD를 넣는다. PRD가 있으므로 부트스트랩은 건너뛴다.
  - 세 역할 모두 haiku를 쓴다. 상한은 `max_total_usd: 1`, `max_iterations: 2`다.
  - 검사 대상은 배관이다. `CURRENT`, REVIEW 블록, `USAGE.csv`, JOURNAL, 템플릿 치환, 권한, 정상 종료를 본다. 코드 품질은 검사하지 않는다.
- 이 테스트로 0007의 첫 실행 보정도 한다. 대상 프로젝트를 정하지 않아도 보정할 수 있다.
- 상세는 `DESIGN.md` 7.1에 있다.

## 검토한 대안
- **실제 연동 테스트 없음(초안)**: 무료지만, 문제를 가장 비싼 시점에 발견한다.
- **`./gradlew test`에 포함**: 빌드할 때마다 비용이 들고, 에이전트 출력이 매번 달라 통과/실패가 일정하지 않다.

## 영향
- 1회에 $0.5~1 정도가 들 것으로 추정한다. 실행 전에 사용자에게 알린다.
- haiku로 실패하면 하네스 문제인지 모델 문제인지 원본 로그로 가려야 한다.
- 작업 규칙을 하나 추가했다(CLAUDE.md). 비용 때문에 범위를 줄이고 싶으면 Claude가 정하지 않는다. 비용과 효과를 함께 보여 주고 사용자의 결정을 받는다.
