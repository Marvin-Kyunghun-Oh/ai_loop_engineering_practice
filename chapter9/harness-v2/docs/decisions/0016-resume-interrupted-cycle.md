# 0016. 중단된 사이클은 성공한 역할을 건너뛰고 이어서 한다

- 상태: 확정
- 날짜: 2026-11-24

## 맥락
- pomodoro-todo 두 번째 실행에서 c7의 generator까지 끝난 뒤 evaluator 실행 전 예산 HALT가 났다. 하네스가 쓴 HALT와 중단(ABORT)은 카운터를 올리지 않으므로 재개하면 c7을 처음부터 다시 돈다.
- 이때 planner는 이미 `[x]`가 된 T16을 건너뛰고 다음 항목을 고른다. T16은 evaluator를 한 번도 거치지 않는다. 사람이 `CURRENT`와 TASKS를 손으로 고쳐야 하는데, 이는 하네스의 목적(사람 개입 없는 루프)에 어긋난다.
- generator의 상한 도달·오류, evaluator의 오류로 사이클이 중단돼도 같은 문제가 생긴다.

## 결정
- 같은 번호의 사이클을 다시 시작할 때, `USAGE.csv`에 `success`로 기록된 역할은 건너뛴다.
  - planner: 성공했고 `CURRENT`가 유효한 항목 ID이면 건너뛴다. `DONE`·`CURRENT` 삭제와 아카이브도 하지 않는다.
  - generator: 성공했으면 건너뛰고 evaluator부터 한다.
- 새 상태 파일은 만들지 않는다. 이미 있는 `USAGE.csv`(사이클, 역할, subtype)를 근거로 쓴다.

## 검토한 대안
- **하네스 HALT도 카운터를 저장**: 재개하면 다음 사이클 번호로 시작해 evaluator를 건너뛴다. 문제가 그대로다.
- **`.cycle_state` 파일에 진행 단계 저장**: 동작은 같지만 USAGE.csv와 이중 기록이 되고 어긋날 수 있다.
- **evaluator가 평가하지 않은 `[x]` 항목을 찾도록 planner 프롬프트에 지시**: 에이전트의 판단에 맡기게 된다.

## 영향
- generator가 상한에 걸려 재시도할 때 planner를 다시 돌리지 않는다. 같은 항목을 이어서 하고 planner 비용($0.35~0.55)이 줄어든다. 항목 자체를 다시 고르게 하고 싶으면 `docs/CURRENT`를 지우면 된다.
- USAGE.csv를 지우거나 고치면 건너뛰기 판단도 달라진다. 이미 비용 복원의 근거 파일이다.
