# PRD: 뽀모도로 할 일 관리 도구 (pomodoro-todo)

- 작성일: 2026-11-24
- 상태: 초안 확정 (Bootstrap 세션 결과)

## 1. 개요

할 일 목록을 관리하면서 각 할 일에 뽀모도로 타이머를 붙여 집중 시간을 기록하는 웹 도구.
할 일을 클릭하면 25분 집중 타이머가 시작되고, 완료된 뽀모도로 횟수가 할 일별로 누적되어 표시된다.

### 목표

- 할 일 단위로 "얼마나 집중했는지"를 뽀모도로 횟수로 남긴다.
- 클릭 한 번으로 집중을 시작할 수 있을 만큼 단순하게 유지한다.

### 비목표 (1차 범위 밖)

- 여러 사용자, 로그인, 기기 간 동기화
- 백엔드 서버, 원격 DB
- 날짜별·주별 통계 화면 (이력 데이터는 저장하되 화면은 나중에)
- 집중·휴식 시간 사용자 설정, 긴 휴식(4회마다 15분)
- 브라우저 Notification, 탭 제목 카운트다운
- 데이터 JSON 내보내기/가져오기
- 모바일 전용 레이아웃 (데스크톱 우선, 좁은 화면에서 깨지지 않는 수준만)

## 2. 사용 범위

- 개인용 단일 사용자. 로그인 없음.
- 한 브라우저(한 origin)의 localStorage에 데이터가 귀속된다.
- 외부 연동 없음. 네트워크 없이 동작한다.
- 여러 탭 동시 실행은 고려하지 않는다. 마지막에 저장한 탭의 상태가 남는다. (자체 결정: 합의)

## 3. 기술 스택

| 항목 | 결정 |
|---|---|
| 프레임워크 | Vue 3 (Composition API, `<script setup>`) |
| 언어 | TypeScript (strict) |
| 빌드 | Vite |
| 상태 관리 | Pinia |
| 테스트 | Vitest + Vue Test Utils (E2E는 1차 범위 밖) |
| 스타일 | UI 라이브러리 없이 직접 CSS |
| 저장소 | 브라우저 localStorage |

## 4. UI 형태

단일 페이지. 상단에 타이머 패널, 그 아래 할 일 목록, 하단에 오늘 합계.

```
+--------------------------------+
|  [보고서 초안 작성]  집중 중   |
|           18:42                |
|   [일시정지]  [취소]          |
+--------------------------------+
| [+ 할 일 추가...          ]     |
| ≡ ☐ 보고서 초안 작성   🍅 3  ✎ 🗑 |
| ≡ ☐ 이메일 정리       🍅 1  ✎ 🗑 |
| ≡ ☑ 회의 준비        🍅 2  ✎ 🗑 |
+--------------------------------+
  오늘 집중: 🍅 6
```

- 타이머 패널: 대상 할 일 제목, 단계(집중 중 / 휴식 중 / 일시정지 / 대기), 남은 시간(mm:ss), 일시정지·재개·취소 버튼.
- 타이머가 없을 때는 "할 일을 클릭해 집중을 시작하세요" 같은 안내를 표시한다.
- 할 일 행: 드래그 핸들(≡), 완료 체크박스, 제목, 누적 뽀모도로 수(🍅 N), 수정(✎), 삭제(🗑).
- 현재 타이머 대상인 할 일 행은 시각적으로 강조한다.

## 5. 핵심 기능

### 5.1 할 일 관리

| ID | 기능 | 설명 |
|---|---|---|
| T1 | 추가 | 입력창에 제목을 입력하고 Enter 또는 추가 버튼. 앞뒤 공백 제거 후 빈 문자열이면 추가하지 않음. 새 항목은 목록 맨 아래에 추가. |
| T2 | 목록 표시 | 사용자가 정한 순서대로 표시. 각 항목에 누적 뽀모도로 수 표시. |
| T3 | 제목 수정 | ✎ 클릭 시 인라인 편집. Enter로 저장, Esc로 취소. 빈 제목은 저장 거부. |
| T4 | 삭제 | 🗑 클릭 시 확인 후 삭제. 타이머 대상인 할 일을 삭제하면 타이머도 취소(미집계). 삭제해도 그 할 일의 완료 이력은 남기며 오늘 합계도 유지한다. (자체 결정: 합의) |
| T5 | 완료 체크 | 체크박스로 완료/미완료 전환. 완료 항목은 취소선 등으로 구분 표시. 목록 위치는 바뀌지 않음. |
| T6 | 순서 변경 | 드래그 앤 드롭으로 순서 변경. 변경된 순서는 저장됨. HTML5 Drag and Drop API를 직접 사용하고 라이브러리를 추가하지 않는다. (자체 결정: 합의) |

### 5.2 뽀모도로 타이머

| ID | 기능 | 설명 |
|---|---|---|
| P1 | 집중 시작 | 할 일 행(제목 영역)을 클릭하면 해당 할 일 대상으로 25분 집중 타이머 시작. 완료 체크된 할 일도 똑같이 집중을 시작할 수 있다. (자체 결정: 합의) |
| P2 | 일시정지·재개 | 집중/휴식 중 일시정지 가능, 재개 시 남은 시간부터 이어서 진행. |
| P3 | 취소 | 진행 중인 집중을 취소하면 그 뽀모도로는 집계하지 않음. 휴식 중 취소는 휴식만 종료. |
| P4 | 집중 완료 | 25분이 지나면 대상 할 일의 누적 횟수 +1, 완료 이력 1건 저장, 알림음 재생, 5분 휴식 타이머로 자동 전환. |
| P5 | 휴식 | 5분 휴식. 휴식은 횟수에 포함하지 않음. 종료 시 알림음 재생 후 대기 상태로 전환(다음 집중을 자동 시작하지 않음). (자체 결정: 합의) |

- 알림음은 Web Audio API로 비프음을 생성한다. 음원 파일을 번들에 넣지 않는다. (자체 결정: 합의)
| P6 | 다른 할 일 클릭 | 집중 진행 중(일시정지 포함)에 다른 할 일을 클릭하면 "현재 뽀모도로를 취소하고 새로 시작할까요?" 확인. 확인 시 기존 것은 미집계 취소 후 새 할 일로 집중 시작. 같은 할 일을 다시 클릭하면 아무 일도 하지 않음. |
| P7 | 휴식 중 할 일 클릭 | 휴식을 종료하고 클릭한 할 일로 바로 집중 시작 (확인 없음). |

타이머 상태 전이:

```
대기 --(할 일 클릭)--> 집중 --(25분 경과)--> 휴식 --(5분 경과)--> 대기
         집중 <--> 일시정지(집중)     휴식 <--> 일시정지(휴식)
         집중/일시정지 --(취소)--> 대기 (미집계)
         휴식/일시정지 --(취소)--> 대기
```

### 5.3 기록 표시

| ID | 기능 | 설명 |
|---|---|---|
| R1 | 할 일별 누적 | 각 할 일 옆에 완료된 뽀모도로 수 표시. |
| R2 | 오늘 합계 | 오늘(브라우저 로컬 시간대 기준 자정~자정) 완료한 뽀모도로 총 수를 하단에 표시. |
| R3 | 완료 이력 저장 | 뽀모도로 완료마다 `{ 할 일 ID, 완료 시각 }`을 저장. 통계 화면은 후속 범위. |

## 6. 타이머 정확도와 복원

- 남은 시간은 `setInterval` 틱 횟수로 세지 않고, **저장된 시각 기준으로 계산**한다
  (예: 종료 예정 시각 − 현재 시각). 백그라운드 탭에서 타이머가 늦게 돌아도 오차가 쌓이지 않게 한다.
- 타이머 상태(단계, 대상 할 일 ID, 종료 예정 시각, 일시정지 시 남은 시간)는 변경될 때마다 localStorage에 저장한다.
- 새로고침·탭 재오픈 시 저장된 시각 기준으로 복원한다.
  - 진행 중이면 남은 시간부터 이어서 표시.
  - 닫혀 있는 동안 집중 25분이 지났다면 **완료로 집계**한다 (누적 +1, 이력의 완료 시각은 실제 종료 예정 시각). 이후 휴식 구간까지 이미 지났다면 대기 상태로, 휴식 중이라면 남은 휴식부터 이어서 표시.
  - 복원 시점에 놓친 알림음은 재생하지 않는다.
  - 일시정지 상태는 남은 시간 그대로 일시정지로 복원한다.
- 복원 대상 할 일이 이미 삭제되어 없으면 타이머를 대기 상태로 초기화한다.

## 7. 데이터 저장

- localStorage, 버전 필드를 둔 단일 JSON 문서(또는 기능별 몇 개 키)로 저장한다. 키 이름과 세부 스키마는 PLAN 단계에서 확정.
- 저장 대상(개념 모델):
  - Task: `id`, `title`, `done`, `order`, `pomodoroCount`, `createdAt`
  - PomodoroRecord: `taskId`, `completedAt`
  - TimerState: `phase`(idle / focus / break), `paused`, `taskId`, `endsAt`, `remainingMs`
- 키 구조: 단일 키에 전체 문서(`version`, tasks, records, timer)를 JSON 하나로 저장한다. (자체 결정: 합의)
- 상태가 바뀔 때마다 즉시 저장한다.
- 스키마에 `version`을 두어 이후 마이그레이션이 가능하게 한다.

## 8. 실패 정책

| 상황 | 처리 |
|---|---|
| localStorage 쓰기 실패 (용량 초과, 접근 불가 등) | 화면에 경고 배너 표시("저장에 실패했습니다. 새로고침하면 변경 사항이 사라질 수 있습니다"). 메모리 상태는 유지하고 앱은 계속 동작. 다음 저장 성공 시 배너 해제. |
| 읽기 시 JSON 파싱 실패 또는 스키마 불일치 | 원본 문자열을 별도 백업 키(예: `...-corrupt-<timestamp>`)에 보관한 뒤 빈 상태로 시작. 화면에 "저장된 데이터를 읽지 못해 초기화했습니다" 안내 표시. |
| localStorage 자체를 사용할 수 없음 (시크릿 모드 제한 등) | 메모리 상태로만 동작하고 경고 배너를 상시 표시. |
| 알림음 재생 실패 (브라우저 자동재생 정책 등) | 오류를 무시하고 화면 상태 전환만 수행. 앱 동작을 막지 않는다. |
| 복원 시 대상 할 일이 없음 | 6절대로 타이머를 대기 상태로 초기화. |

## 9. 품질 요구사항

- 타이머 상태 전이, 시각 기준 남은 시간 계산, 복원 로직, 저장소 실패 처리는 단위 테스트로 검증한다. 시간은 주입 가능한 시계(또는 Vitest fake timers)로 테스트한다.
- 할 일 CRUD와 순서 변경은 스토어 단위 테스트, 주요 화면 상호작용은 컴포넌트 테스트로 검증한다.
- 최신 Chrome, Edge, Firefox 데스크톱에서 동작.
