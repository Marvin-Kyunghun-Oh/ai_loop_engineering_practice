## 자체 결정

- 작업 항목 ID는 PRD 기능 ID(T1~T6)와 혼동되지 않게 T10부터 매긴다.
- 프로젝트 생성기(npm create) 없이 설정 파일을 직접 작성한다. 허용 명령이 npm install, npx vitest, npx vue-tsc뿐이기 때문이다.
- 테스트는 `tests/` 아래에 `src/` 구조를 따라 `*.spec.ts`로 두고, Vitest 환경은 jsdom으로 한다. Vue Test Utils 표준 구성이라서.
- 스토어의 시계·ID 주입은 `create*Store` 팩토리로 한다(T12 리뷰 핵심 결정). 테스트마다 fake clock을 쉽게 넣기 위해서.
- 타이머 규칙은 `src/domain/timer.ts` 순수 함수로 두고 스토어는 연결만 한다. 상태 전이와 복원을 시계 없이 단위 테스트하기 위해서.
- 복원(6절)은 시간 경과 처리 함수(`advance`)를 재사용한다. 닫힌 동안의 집중·휴식 경과 규칙을 한 곳에 두기 위해서.
- 저장 키는 `pomodoro-todo`, 문서는 `{ version: 1, tasks, records, timer }`이고 필드는 PRD 7절 개념 모델을 그대로 쓴다. 합의된 단일 키 구조에 이름만 붙인 것이라서.
- 손상 데이터 백업 키는 `pomodoro-todo-corrupt-<epoch ms>`로 한다. PRD 8절 예시 형식을 따른다.
- 스키마 검증은 라이브러리 없이 직접 작성한다. 의존성 추가를 피하기 위해서.
- 저장소를 쓸 수 없으면 변경 시 저장을 시도하지 않고 saveFailed 대신 storageUnavailable 배너만 쓴다. PRD 8절이 두 상황을 다른 처리로 나누기 때문이다.
- 삭제·P6 확인 대화상자는 `window.confirm`을 쓴다. 가장 단순하고 테스트에서 spy로 대체하기 쉽다.
- 컴포넌트는 전역 스토어(`use*Store`)를 쓰고 시간은 fake timers로 테스트한다. 기본 스토어가 systemClock을 쓰기 때문이다.
- 알림음은 App의 주기 tick 이벤트로만 재생하고 마운트 직후 tick은 재생하지 않는다. PRD 6절이 복원 시 놓친 알림음을 재생하지 않게 하기 때문이다.
- 저장 경고·초기화 안내 배너는 App이 영속화 스토어 상태로 그리며 닫기 버튼 없이 상태가 true인 동안만 보인다. 가장 단순한 형태라서.
- 좁은 화면 기준은 480px 이하로 한다. 데스크톱 우선, 깨지지 않는 수준만 요구하므로 단일 구간이면 충분하다.
