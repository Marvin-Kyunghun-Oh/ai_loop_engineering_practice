# PRD: rss-wiki

> RSS/Atom 피드에서 글을 수집하고, Claude Code CLI로 한국어 요약을 만들어 Markdown 위키로 정리하는 개인용 로컬 웹 앱

- 작성일: 2026-11-23
- 상태: 초안 v1

---

## 1. 배경과 목표

### 배경
구독하는 피드가 늘어나면 새 글을 일일이 읽기 어렵고, 읽은 내용도 나중에 다시 찾기 어렵다.

### 목표
- 등록한 피드의 새 글을 버튼 한 번으로 수집하고 한국어로 요약한다.
- 요약 결과를 **사람이 읽을 수 있고 다른 도구(Obsidian 등)에서도 열 수 있는 Markdown 위키**로 쌓는다.
- 피드, 태그, 키워드로 지난 요약을 빠르게 찾는다.

### 비목표 (v1 범위 밖)
- 여러 사용자, 인증, 원격 배포
- 기존 RSS 리더 서비스(Feedly, Miniflux, FreshRSS 등) API 연동
- 주기적 자동 실행(스케줄러). 수동 실행만 지원한다.
- Claude Code CLI 외의 LLM 제공자(Claude API 직접 호출, Ollama 등)
- 기간별 다이제스트 문서 생성
- 글을 읽었는지 여부(읽음/안 읽음) 관리. DB에 읽음 플래그를 두지 않는다. (자체 결정: 합의)
- 오래된 글 정리(보존 기간). DB 레코드와 위키 파일을 모두 영구 보존한다. (자체 결정: 합의)

## 3. UI 형태

**로컬 웹 앱**: FastAPI 서버에서 Jinja2 템플릿을 서버 렌더링하고, 부분 갱신에는 htmx를 쓴다. Node 빌드 체인은 두지 않는다.

- 실행: `rss-wiki serve` (기본 `http://127.0.0.1:8000`, 포트는 설정으로 바꿀 수 있음)
- 기존 `pyproject.toml`의 `rss-wiki` 엔트리포인트를 CLI 진입점으로 쓴다. v1에서 CLI는 서버 실행과 최소한의 보조 명령만 맡는다.

### 화면 구성

1. **요약 목록 / 상세**
   - 최신순 목록: 제목, 피드명, 게시일, 3줄 요약 미리보기, 태그
   - 피드 필터, 태그 필터
   - 상세: 3줄 요약, 태그, 원문 링크, 메타데이터(게시일, 수집일, 본문 출처: 원문 추출 / 피드 본문)
   - 목록과 상세는 DB 사본을 렌더링한다(Markdown 파일을 다시 읽지 않는다). (자체 결정: 합의)
2. **피드 관리**
   - 피드 URL 추가 (추가할 때 피드를 파싱해서 제목을 자동으로 채우고, 유효하지 않으면 거부)
   - 피드 삭제, 비활성화/활성화
   - OPML 가져오기 (기존 리더의 구독 목록을 옮기는 용도)
3. **실행 / 상태**
   - "새 글 가져오기" 버튼: 수집과 요약을 백그라운드 작업으로 시작
   - 진행 상황 표시(htmx 폴링): 단계, 처리 건수, 실패 건수
   - 실행이 이미 진행 중이면 새로 시작하지 않는다(동시 실행 1개).
   - 실패 목록: 피드/글별 오류 메시지, 시도 횟수, 수동 재시도 버튼
4. **검색**
   - 제목과 요약 텍스트 전문 검색 (SQLite FTS5)

## 4. 핵심 기능

### 4.1 피드 수집
- 활성화된 피드의 RSS/Atom을 가져와 새 글을 찾는다.
- 글 식별: 항목의 `guid`/`id`를 우선 쓰고, 없으면 정규화한 `link`를 쓴다. 이미 저장된 글은 건너뛴다.
- 조건부 요청(`ETag`, `Last-Modified`)으로 바뀌지 않은 피드는 다시 받지 않는다.

### 4.2 본문 확보
1. 글의 원문 링크 페이지를 가져와 본문을 추출한다(예: trafilatura).
2. 추출에 실패하거나 본문이 너무 짧으면 피드의 `content` → `summary` 순서로 대신 쓴다.
3. 어떤 본문을 썼는지(`extracted` / `feed`)를 기록한다.
4. LLM에 넘기는 본문은 최대 길이를 정해 자른다(설정값).

### 4.3 요약 (Claude Code CLI)
- 글마다 Claude Code CLI를 비대화형으로 호출한다(`claude -p ...`).
  - 지시문(출력 형식, 기존 태그 목록 포함)만 `-p` 인자로 넘기고, 본문은 표준 입력(stdin)으로 전달한다. (자체 결정: 합의)
  - 모델은 설정값 `claude_model`로 지정한다. 값이 없으면 `--model`을 붙이지 않고 CLI 기본 모델을 쓴다. (자체 결정: 합의)
  - 요약은 순차로 처리한다(동시 1개). (자체 결정: 합의)
- 출력 형식은 **한국어**(원문 언어와 상관없음)로 다음을 포함한다.
  - **3줄 요약**: 핵심 내용 3문장
  - **태그**: 3~5개
- CLI 응답은 구조화된 형식(JSON)으로 받아 검증한다. 형식이 틀리면 요약 실패로 처리한다.
- 호출마다 타임아웃을 둔다(설정값).
- Windows에서는 `claude.cmd`를 실행할 수 있어야 한다. 실행 파일 경로는 설정으로 바꿀 수 있게 한다.

### 4.4 태그 정책
- 프롬프트에 **기존 태그 목록**을 넣어 가능하면 재사용하게 한다.
- 저장할 때 정규화한다: 소문자, 케밥케이스, 앞뒤 공백 제거, 중복 제거.

### 4.5 처리량 제한
- 피드를 **처음 등록한 뒤 첫 수집** 때는 최근 **10개** 글만 요약 대상으로 삼는다. 나머지 과거 글은 "건너뜀(backfill 제외)"으로 기록한다.
- **실행 1회당 최대 50개** 글까지만 요약한다. 남은 글은 "대기" 상태로 두고 다음 실행 때 처리한다.
- 두 값 모두 설정으로 바꿀 수 있다.

### 4.6 Markdown 위키 생성
- 위키 루트 경로는 설정으로 정한다(기본 `./wiki`, Obsidian vault 안의 폴더도 지정할 수 있음).
- 구조:
  ```
  wiki/
    index.md                         # 최신 요약 목록 (자동 생성)
    articles/YYYY/MM/{slug}.md       # 글별 요약 (게시일 기준)
    feeds/{feed-slug}.md             # 피드별 인덱스 (자동 생성)
    tags/{tag}.md                    # 태그별 인덱스 (자동 생성)
  ```
- 글별 파일 형식:
  ```markdown
  ---
  title: "..."
  feed: "..."
  url: "https://..."
  published: 2026-11-20T09:00:00+09:00
  fetched: 2026-11-23T19:00:00+09:00
  source: extracted   # extracted | feed
  tags: [llm, rss]
  ---

  # {제목}

  - 요약 1
  - 요약 2
  - 요약 3

  [원문 보기](https://...)
  ```
- 인덱스 파일(`index.md`, `feeds/`, `tags/`)은 실행이 끝날 때마다 DB를 기준으로 **전체를 다시 생성**한다(변경분만 갱신하지 않는다). (자체 결정: 합의)
- 같은 글을 다시 요약하면(수동 재시도) 글 파일을 덮어쓴다. 사용자가 직접 고친 내용을 감지하거나 보존하지 않는다. (자체 결정: 합의)
- slug 충돌은 접미사(`-2`, `-3` …)로 해결한다. 파일명은 Windows에서 쓸 수 없는 문자를 제거한다.
- 파일 쓰기는 임시 파일에 쓴 뒤 이름을 바꾸는 방식(원자적 쓰기)으로 한다.

## 5. 데이터 저장

| 데이터 | 저장소 | 비고 |
|---|---|---|
| 피드 목록, 피드 상태(ETag 등) | SQLite | |
| 글 메타데이터, 처리 상태, 시도 횟수, 오류 메시지 | SQLite | |
| 요약, 태그 | SQLite + Markdown | **Markdown 파일이 정본.** DB에는 목록, 필터, 검색용 사본을 둔다. |
| 검색 인덱스 | SQLite FTS5 | 제목 + 요약 |
| 실행 이력 | SQLite | 시작/종료 시각, 처리/실패 건수 |
| 설정 | 설정 파일 (TOML) | 위키 경로, DB 경로, 포트, 처리량 상한, 타임아웃, CLI 경로 등 |

- SQLite는 표준 라이브러리 `sqlite3`를 쓴다.
- 추출한 원문 본문은 저장하지 않는다(DB와 위키 파일 모두). (자체 결정: 합의)
- 글 레코드는 영구 보존한다(보존 기간에 따른 정리 없음). (자체 결정: 합의)

### 글 처리 상태
```
new → fetching_content → summarizing → done
                 ↘ failed (attempts < 3 이면 다음 실행에서 재시도)
                 ↘ failed_permanent (attempts ≥ 3, UI 수동 재시도로만 복구)
skipped_backfill (최초 등록 시 최근 N개 밖의 글)
```

## 6. 외부 연동

| 대상 | 용도 | 비고 |
|---|---|---|
| RSS/Atom 피드 URL | 글 목록 수집 | HTTP GET, User-Agent는 일반 클라이언트명으로 지정 |
| 글 원문 웹페이지 | 본문 추출 | |
| Claude Code CLI (`claude`) | 요약과 태그 생성 | 로컬에 설치하고 로그인해 둬야 함. API 키는 따로 관리하지 않음 |

- 외부 HTTP 요청에는 타임아웃을 두고, 같은 호스트에 너무 자주 요청하지 않는다.

## 7. 실패 정책

**기본 원칙: 실패한 대상은 건너뛰고 기록한 뒤 나머지를 계속 처리한다. 한 건이 실패해도 실행 전체를 멈추지 않는다.**

| 실패 상황 | 처리 |
|---|---|
| 피드 가져오기 실패 (네트워크, HTTP 오류, 파싱 오류) | 그 피드만 건너뛴다. 피드에 마지막 오류와 연속 실패 횟수를 기록하고 UI에 표시한다. 다음 실행 때 다시 시도한다. |
| 원문 본문 추출 실패 | 실패로 치지 않는다. 피드 본문으로 대신 쓴다. |
| 원문도 피드 본문도 없음 | 글을 `failed`로 기록한다. |
| Claude Code CLI 호출 실패 (타임아웃, 0이 아닌 종료 코드, JSON 형식 오류) | 글을 `failed`로 기록하고 `attempts`를 1 올린다. |
| 재시도 | `failed`이면서 `attempts < 3`인 글은 다음 실행에서 자동으로 다시 처리한다. 3회째 실패하면 `failed_permanent`로 바꾸고 UI 수동 재시도로만 처리한다. |
| Claude Code CLI를 찾을 수 없음 / 로그인 안 됨 | 실행을 시작할 때 사전 점검하고, 실패하면 요약 단계를 시작하지 않는다. 사용자가 고칠 방법을 UI에 보여준다. (수집은 진행할 수 있다.) |
| 위키 파일 쓰기 실패 | 그 글을 `failed`로 기록한다. DB와 파일이 어긋나지 않도록 파일 쓰기에 성공한 뒤에 `done`으로 바꾼다. |
| 서버가 실행 도중 종료됨 | 다음에 시작할 때 `fetching_content` / `summarizing` 상태에 남은 글을 `new`로 되돌린다. |

## 8. 비기능 요구사항

- **멱등성**: 같은 실행을 반복해도 글이 중복 저장되거나 요약이 중복 생성되지 않는다.
- **테스트 가능성**: 피드 가져오기, 본문 추출, Claude Code CLI 호출은 인터페이스 뒤로 분리해 테스트에서 가짜 구현으로 바꿀 수 있게 한다. 테스트에서는 실제 네트워크와 CLI를 호출하지 않는다.
- **이식성**: 경로는 `pathlib`로 처리한다. Windows와 POSIX 양쪽에서 동작해야 한다.
- **로그**: 실행마다 처리 결과를 로그로 남긴다(파일 + 콘솔).

## 9. 완료 기준 (v1)

1. `rss-wiki serve`로 서버를 띄우고 브라우저에서 피드를 추가할 수 있다.
2. "새 글 가져오기"를 누르면 새 글이 수집·요약되고, `wiki/` 아래에 글별 Markdown 파일과 index/feeds/tags 인덱스가 생긴다.
3. 목록 화면에서 피드와 태그로 거를 수 있고, 검색 화면에서 키워드로 요약을 찾을 수 있다.
4. 일부 피드나 글이 실패해도 나머지는 처리되고, 실패 목록에 나타나며 재시도할 수 있다.
5. 같은 실행을 다시 해도 중복이 생기지 않는다.
6. OPML 파일로 피드를 일괄 등록할 수 있다.
