# RSS Wiki

RSS 피드의 새 글을 Claude CLI(`claude -p`)로 요약·분류하고, **주제(카테고리)별로 누적되는 위키 페이지**로 정리해 주는 개인용 로컬 웹 도구입니다. 설계는 [`docs/PRD.md`](docs/PRD.md)를 따릅니다.

## 사전 준비

- Python 3.11+, [uv](https://docs.astral.sh/uv/)
- [Claude Code CLI](https://claude.com/claude-code)(`claude`)가 설치되어 있고 로그인된 상태 (LLM 호출은 이 CLI의 `-p` 모드를 사용하므로 별도 API 키가 필요 없습니다)

## 실행

```bash
uv sync
uv run uvicorn rss_wiki.main:app --host 127.0.0.1 --port 8000
```

- 브라우저에서 <http://127.0.0.1:8000> 을 엽니다. 인증이 없으므로 외부에 노출하지 마세요.
- DB는 `./data/rss-wiki.db`, 로그는 `./data/logs/rss-wiki.log`에 생깁니다(앱 시작 시 자동 생성).
- **수집은 앱이 실행 중일 때만** 돕니다. 앱 안의 스케줄러(APScheduler)가 매시 정각에 실행하고, UI의 *Fetch now* 버튼 또는 `curl -X POST http://127.0.0.1:8000/api/fetch`로 바로 실행할 수 있습니다(이미 실행 중이면 409).
- **수집 상태 표시:** 수집이 돌고 있으면 모든 화면 상단에 "수집 중…"이 뜨고 *Fetch now* 버튼이 잠깁니다. 끝나면 페이지가 자동으로 한 번 새로고침되고 결과(새 글·요약·위키 갱신 수, 실패 건수)가 잠시 표시됩니다. 스케줄러가 시작한 수집도 화면을 열어 두면 똑같이 보입니다. 상태는 `GET /api/fetch/status`(JSON)로도 조회할 수 있습니다.

## 화면

| 경로 | 내용 |
|---|---|
| `/` | 최상위 카테고리 목록(새 업데이트가 있는 것이 위) |
| `/categories/{id}` | 위키 페이지 + 원문 링크. 방문하면 읽음 처리 |
| `/categories/manage` | 이름 수정 · 병합 · 상위 카테고리 지정(2단계까지) |
| `/feeds` | 피드 추가·삭제·활성/비활성 |
| `/search?q=` | 제목·요약·본문 키워드 검색(SQLite FTS5) |
| `/logs` | 작업 로그 최근 200건 |
| `/api/fetch/status` | 수집 진행 상태 JSON(`running`, `last_error`, `last_report`) |

## 동작 요약

1. 활성 피드를 병렬(최대 5)로 가져와 새 글(URL 기준)을 찾습니다.
2. 링크에서 본문을 추출하고(실패 시 RSS 요약), Claude로 한국어 요약과 카테고리를 만듭니다.
3. 새 글이 들어온 카테고리의 위키 페이지를 **사이클당 1회** 증분 재구성합니다.
4. 네트워크·프로세스 오류는 2s→4s→8s 지수 백오프로 최대 3회 재시도하며, 모든 실패는 `/logs`에 남습니다. 피드는 자동으로 비활성화하지 않습니다.

## 테스트

```bash
uv run pytest              # 전체 158건 (단위 128 + E2E 30), 약 40초
uv run pytest tests/e2e    # E2E만
```

- **단위 테스트**는 네트워크·`claude` CLI·trafilatura를 가짜로 대체하므로 오프라인에서 돕니다.
- **수집 상태 스크립트**(`base.html`)는 브라우저 대신 node로 실행해 검증합니다(`tests/test_fetch_status_js.py`, node가 없으면 건너뜀). 실제 브라우저에서의 모양은 확인하지 않았습니다.
- **E2E 테스트**(`tests/e2e/`)는 실제 uvicorn 서버, SQLite, feedparser, trafilatura를 쓰고 로컬 모의 RSS 사이트와 가짜 `claude` 스크립트만 대체합니다. TC 목록과 결과, 발견·수정한 결함은 [`docs/QA_TC.md`](docs/QA_TC.md)를 보세요.
- **실제 인터넷 피드와 실제 `claude` CLI로는 자동 테스트하지 않았습니다.** 처음 쓸 때는 피드 1~2개로 *Fetch now*를 눌러 `/logs`를 확인하세요.

## 알려진 한계

- **검색:** PRD대로 FTS5 `unicode61` 토크나이저를 씁니다. 공백 단위 토큰과 접두 일치만 되므로 `에이전트`로 `멀티에이전트`(단어 중간)는 찾지 못합니다. 한국어 부분 일치가 필요하면 `trigram` 토크나이저로 바꾸는 것을 검토하세요.
- **수집은 글을 한 건씩 순차 처리합니다**(`claude -p` 호출 직렬화). 새 글이 많으면 한 사이클이 오래 걸리고, 그동안 *Fetch now*는 막힙니다. 재구성 병렬화는 검토 후 보류했습니다(`/logs`의 시간으로 병목을 확인한 뒤 결정).
- **병합은 되돌릴 수 없습니다.** 병합된 카테고리 행은 남기지만(LLM이 옛 이름을 제안해도 대상으로 연결하기 위함) UI에서 복원하는 기능은 없습니다.
- **사내망·로컬 주소 피드:** trafilatura가 127.0.0.1·사설 IP의 원문 다운로드를 SSRF 보호로 차단합니다. 이런 피드는 본문 추출이 실패해 RSS 발췌로 대체됩니다(오류는 아님).
- 위키 재구성은 LLM 출력의 필수 섹션(`# 제목`, `## 한줄 요약`, `## 핵심 내용`)만 검증합니다. 내용의 사실 여부는 검증하지 않습니다.
