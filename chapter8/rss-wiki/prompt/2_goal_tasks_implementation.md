## 프롬프트

슬래시 커맨드 `/goal`로 실행했다. (직전에 `/model`로 모델을 Sonnet 5.5로 바꿨다.)

```
/goal `docs/TASKS.md`의 모든 항목이 [x]로 바뀌고 `uv run pytest`가 종료 코드 0으로 끝난다.
TASKS.md가 없으면 `docs/PRD.md`를 기반으로 먼저 작성한다.
한 번에 하나의 TASK만 구현 (가장 중요)
막히면 그 항목에 'BLOCKED'를 적고 다음 항목으로 넘어간다.
같은 테스트 실패가 3번 반복되면 중단하고 실패 원인을 요약한다.
또는 20턴 후 중단한다.

모든 작업이 끝나면 `(프롬프트)`의 정책에 따라 정리할 것!
```

확장된 프롬프트: 위 조건을 세션 Stop 훅의 종료 조건으로 걸고, 조건이 만족될 때까지 멈추지 말고 작업하라는 지시가 붙는다.

## 답변

### 처리 절차 (순차 요약)
1. **환경 확인:** `chapter8/rss-wiki`에는 `CLAUDE-local.md`, `docs/PRD.md`, `prompt/`만 있었다. uv 0.13.9와 Python 3.15가 있는 것을 확인했다.
2. **TASKS.md 작성:** 없어서 PRD 기반으로 TASK 13개를 만들었다. 네트워크와 LLM은 모두 주입 가능한 함수로 만들고, 테스트에서는 가짜로 대체하기로 했다.
3. **한 턴에 TASK 하나씩 구현:** 구현 → 테스트 작성 → `uv run pytest` 통과 확인 → `[x]` 체크 순서로 진행했다.

### 중간에 바꾼 점
- **T11:** 위키를 다시 만들 주제를 명시적으로 표시하려고 `topics.needs_refresh` 컬럼을 T2의 스키마에 추가했다. `topics.py`, `wiki.py`도 함께 고쳤다. 아직 만들어진 DB가 없어서 마이그레이션은 필요 없었다.
- **T12:** 수집기가 `content_source`를 채우면 본문 확보 단계에서 미확인 글을 구분할 수 없다. 그래서 수집기는 이 값을 비워 두고, 본문 확보 단계가 결정하도록 고쳤다.

### 결과
- **목표 조건 충족:** TASKS.md의 13개 항목이 모두 `[x]`이고, `uv run pytest`는 91개 통과, 종료 코드 0이다.
- **막힌 항목 없음:** `BLOCKED`로 표시한 항목은 없다. 같은 테스트 실패가 반복된 적도 없다. 사용한 턴은 20턴 이내다.
- **만든 파일:** `pyproject.toml`, `.gitignore`, `src/rss_wiki/` 모듈 12개, `tests/` 테스트 파일 12개, `docs/TASKS.md`
- **커밋:** 하지 않았다.

### 검증하지 못한 부분
- 실제 네트워크 어댑터(`httpx_fetcher`, `trafilatura_extractor`, `make_anthropic_llm`)는 테스트에서 가짜로 대체했다. 실제 피드와 API 키로 `rss-wiki run`을 한 번 돌려봐야 한다.
- 웹 UI는 홈·주제·검색 3개 화면만 있다. PRD의 글 상세(재분류 화면), 피드 관리, 실행 기록, 병합 되돌리기 화면은 TASKS 범위 밖이라 구현하지 않았다. 재분류 로직(`reclassify_article`)은 있지만 화면은 없다.
