## 프롬프트

`/goal` 슬래시 커맨드(확장 후):

```
RSS Wiki를 QA하려고 해.
TC를 만들고, E@E 테스트를 해서 잘 동작하는지 확인해줘.
(프롬프트)
```

- "E@E"는 E2E의 오타로 해석했다.
- 진행 모드: 일반 실행. 이전 대화에서 이어진 세션이며, 커밋 요청("현재 내용 커밋해줄래?")은 이 `/goal`로 중단돼 아직 수행하지 않았다.

## 답변

### 1. 방침
기존 단위 테스트 115개는 네트워크·CLI·추출기를 모두 가짜로 대체해서, 실제 HTTP·스레드·DB가 엮인 동작은 검증된 적이 없었다. 그래서 외부 세계만 로컬로 대체하고 나머지는 실제 부품을 쓰는 E2E를 만들기로 했다.

### 2. 처리 절차
1. PRD §3·§7·§9·§10과 라우트·스키마를 읽어 검증할 동작을 정했다.
2. E2E 하네스를 만들었다(`tests/e2e/`).
   - 로컬 모의 사이트(RSS·원문 HTML, 상태 코드 조작 가능)
   - 가짜 `claude` 스크립트(subprocess·stdin/stdout 경로는 실제 그대로, 제목 마커로 실패·코드펜스 제어)
   - 스레드로 띄운 실제 uvicorn 서버 + httpx 클라이언트
3. TC 24개(테스트 29건, 파라미터 포함)를 작성하고 실행했다. 영역은 기동·피드 관리·수집 파이프라인·실패 처리·검색·카테고리 편집·보안·영속성이다.
4. 실패를 분석하고 고쳤다.
5. TC 문서 `docs/QA_TC.md`와 README 링크를 작성했다.

### 3. 중간에 부딪힌 문제
| 문제 | 원인 | 처리 |
|---|---|---|
| 본문 추출이 항상 RSS 발췌로 대체됨 | trafilatura가 127.0.0.1을 SSRF 보호로 차단 | 테스트 동안만 `DEFAULT_CONFIG`의 `SSRF_PROTECTION`을 끔. 운영상 관찰 사항으로 문서화 |
| 동시 요청 시 500 (G3 실패) | **실제 버그**: SQLite 연결이 만든 스레드와 다른 스레드에서 사용됨 | `db.connect`에 `check_same_thread=False`, 회귀 테스트 추가 |
| 검색 단언 실패 | 하이라이트가 제목을 `<mark>`로 쪼갬(알려진 동작) | 단언을 실제 출력으로 수정 |
| 내가 쓴 단언 3곳이 `or True` 등으로 항상 통과 | 작성 실수 | 구체적인 단언으로 교체 |
| `from conftest import Server` 실패 | 상위 `tests/conftest.py`와 이름 충돌 | 상대 임포트로 변경 |

### 4. 결과
- `uv run pytest`: **145 passed, 종료 코드 0** (기존 115 + 단위 회귀 1 + E2E 29).
- E2E를 3회 연속 돌려 모두 29건 통과했다(불안정 없음).
- 결함 1건 발견·수정: 동시 요청 시 간헐적 HTTP 500(BUG-1).
- 검증하지 못한 것: 실제 `claude` CLI 품질, 실제 인터넷 피드, 매시 정각 cron의 실제 발화, 대규모 성능, 브라우저 시각 검증. 자세한 내용은 `docs/QA_TC.md` §5.
