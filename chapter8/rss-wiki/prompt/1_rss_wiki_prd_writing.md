## 답변

### 1. 현황 파악
- 프로젝트 폴더(`chapter8/rss-wiki`)에는 `CLAUDE-local.md`만 있어, 백지 상태에서 PRD를 새로 쓰기로 했다.
- `CLAUDE-local.md`의 규칙(문서와 대화는 한국어)을 확인했다.

### 2. 원안에서 빠진 항목 짚기
원안에 더하면 좋을 항목 11가지를 먼저 제시했다.
1. 대상 사용자와 사용 환경(혼자 로컬에서 쓰는지, 여러 사람이 쓰는지)
2. 실행 주기(수동 실행인지, 정해진 시각에 자동 실행인지)
3. 본문 확보(RSS에는 발췌만 있는 경우가 많음)
4. 중복 처리(같은 글이 여러 피드에 올라오거나, 같은 사건을 여러 매체가 다루는 경우)
5. 주제 체계 관리("주제 10개" 목표를 지키려면 주제가 계속 늘어나는 것을 막아야 함)
6. 위키 누적 방식(덧붙이기만 하면 페이지가 끝없이 길어짐)
7. 출처 보존과 환각 방지
8. LLM 비용과 모델 선택
9. 요약 언어
10. 분류 오류 수정
11. 비목표, 성공 지표, 기술 스택

### 3. 대화로 미결정 사항 정하기
질문 묶음 세 번(질문 12개)으로 다음을 정했다.

| 항목 | 결정 |
|---|---|
| UI | 로컬 웹 UI(CLI 병행) |
| 주제 체계 | LLM이 완전 자동으로 생성 |
| 주제 상한 초과 | LLM이 자동 병합하고 이력을 남김(되돌리기 가능) |
| 페이지 구성 | 상단 "현재 동향 요약"은 다시 쓰고, 하단에는 날짜별 글 목록. 오래된 항목은 월별 아카이브로 |
| 실행 주기 | 수동 실행 + cron/launchd로 매일 실행 지원 |
| 검색 | SQLite FTS5 키워드 전문검색 |
| 수집 실패 | 지수 백오프로 3회 재시도. 5회 연속 실패하면 피드 자동 비활성화. LLM 실패 글은 미처리 큐에 남김 |
| 본문 수집 | RSS 본문이 짧을 때(500자 미만)만 원문에서 추출 |
| LLM / 언어 | Claude API(글 처리는 Haiku, 위키·병합은 Sonnet). 결과는 한국어 |
| 사용자 수정 | 글 재분류만 지원 |
| 중복 처리 | URL·GUID가 같은 글만 제거 |
| 스택 | Python + FastAPI + Jinja2/HTMX + SQLite |

### 4. 계획 수립과 승인
- 확정한 결정, 에이전트가 정한 기본값, PRD 문서 구조를 계획 파일로 정리했다.
- Plan 모드를 끝내며 계획을 승인받았다.

### 5. PRD 작성
`docs/PRD.md`를 다음 11개 장으로 작성했다.
1. 개요 2. 목표/비목표 3. 대상 사용자와 시나리오 4. 기능 요구사항(피드·수집·LLM·주제·위키·웹 UI·검색·CLI·스케줄, P0/P1 구분) 5. 실패 처리 정책 6. 데이터 모델 초안 7. 비기능 요구사항 8. 기술 스택 9. 성공 지표 10. 마일스톤(M1~M5) 11. 남은 질문

에이전트가 기본값으로 정해 넣은 것은 다음과 같다.
- 위키 요약의 모든 문장에 근거 글 번호(`[n]`)를 달고, 번호가 실제 글과 맞는지 검증(환각 방지)
- 실행 1회당 처리할 글 상한 100개, 처음 구독한 피드는 최근 글 10개만 수집(비용 보호)
- 한국어 검색을 위한 FTS5 trigram 토크나이저
- 사용자가 직접 바꾼 분류는 이후 자동 병합 때도 유지
- 주제 URL은 ID 기반이라 이름이 바뀌어도 링크가 유지됨
- 웹 서버는 `127.0.0.1`에만 바인딩, 인증 없음
- `run`은 같은 실행을 반복해도 결과가 같고(멱등), 잠금 파일로 동시 실행을 막음

- 남은 질문: 요약 길이, 아카이브 기간·주제 상한이 적절한지, 글 하나에 주제를 여러 개 붙일지
