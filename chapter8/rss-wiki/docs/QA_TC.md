# QA 테스트 케이스 (TC) 와 E2E 결과

대상: RSS Wiki v0.1 (`docs/PRD.md`). 실행: `uv run pytest` (전체 158건) 또는 `uv run pytest tests/e2e` (E2E 30건, 약 30초).

## 1. E2E 방식

실제 구성요소를 최대한 그대로 쓰고, 외부 세계만 로컬로 대체했다.

| 구성요소 | E2E에서의 상태 |
|---|---|
| FastAPI 앱, uvicorn, Jinja2, SQLite(FTS5·WAL), APScheduler | **실제** (스레드로 띄운 uvicorn에 httpx로 실제 HTTP 요청) |
| feedparser, httpx 다운로드, trafilatura 본문 추출 | **실제** (로컬 모의 사이트에서 RSS·원문 HTML을 받아 옴) |
| `claude` CLI | **가짜 스크립트** (`tests/e2e/fake_claude.py`): 실제 subprocess·stdin/stdout 경로는 그대로 타되, 응답은 결정적 |
| RSS 사이트 | 로컬 `ThreadingHTTPServer` (`tests/e2e/conftest.py`의 `Site`): 상태 코드·피드 내용을 테스트가 바꿈 |

하네스 보조: LLM 재시도 대기(2/4/8초)는 0.01초로 줄이고, trafilatura의 SSRF 보호(127.0.0.1 차단)는 테스트 동안만 끈다.

## 3. 발견한 결함

### BUG-1 (수정 완료): 동시 요청 시 간헐적 HTTP 500
- **증상**: 화면 요청이 겹치면 `sqlite3.ProgrammingError: SQLite objects created in a thread can only be used in that same thread` 로 500 응답. 수집 중 여러 화면을 열면 재현됨(G3에서 3회 모두 실패).
- **원인**: FastAPI가 동기 의존성(`get_conn`)과 동기 엔드포인트를 서로 다른 스레드풀 스레드에서 실행하는데, 연결이 기본값 `check_same_thread=True`였다. 기존 115개 단위 테스트는 요청을 하나씩 보내서 잡지 못했다.
- **수정**: `src/rss_wiki/db.py`의 `connect()`에 `check_same_thread=False`. 연결은 요청 하나가 순차로만 쓴다.
- **회귀 테스트**: `tests/test_db.py::test_connection_usable_from_another_thread`, E2E G3.

## 4. 관찰 사항 (결함은 아니지만 알아둘 것)

1. **trafilatura SSRF 보호**: 설치된 trafilatura는 127.0.0.1·사설망 주소의 원문을 기본 차단한다. 사내망(인트라넷) 피드는 본문 추출이 실패하고 RSS 발췌로 대체된다(PRD의 대체 동작이라 오류는 아님). 필요하면 설정으로 풀어야 한다.
2. **한국어 단어 중간 검색 불가**: `unicode61` 토크나이저 특성. 접두 검색은 된다(예: "에이전트" → "에이전트가" 적중, "전트" → 미적중).
3. **하이라이트가 제목을 쪼갬**: 검색어가 제목에 있으면 `AI <mark>에이전트</mark> 입문`처럼 나온다. 정상이다.

## 5. 검증하지 못한 것

- 실제 `claude` CLI의 응답 품질과 JSON 준수율(가짜 CLI로 대체했다). 실제 CLI 호출은 비용·비결정성 때문에 자동화하지 않았다.
- 실제 인터넷 피드(인코딩·리다이렉트·대용량 피드)와 매시 정각 cron의 실제 발화(스케줄 등록만 확인했다).
- 입력 100,000자 가드·글 수백 개 규모의 성능(단위 테스트로만 확인).
- 브라우저 렌더링(HTML 구조와, 수집 상태 스크립트의 로직만 node로 확인했다. 배너 모양·스피너 등 시각 검증은 하지 않았다).
